# Архитектура MapVault

## Выбор стека и причины

| Решение | Почему |
|---|---|
| **Node.js 22 + чистый JS (ESM)** | Один язык для сервера и интерфейса; встроенные `node:sqlite`, `fetch`, `node:test` — почти без зависимостей |
| **SQLite через `node:sqlite`** | Встроен в Node: нет нативных модулей, exe собирается одним файлом. WAL + `synchronous=FULL`: подтверждённый score переживает сбой питания. FTS5 для поиска |
| **Локальный HTTP-сервер + SPA без сборки** | Интерфейс — обычный сайт на `localhost`, без фреймворков и бандлера: нечему ломаться, легко править |
| **rosu-pp (WASM)** | Проверенная реализация сложности/pp osu! (используется Tosu и ботами), а не самописная формула |
| **Node SEA (Single Executable Application)** | Официальный способ Node собрать один `MapVault.exe`; работает кросс-сборка с Linux; интерфейс и WASM встроены как ресурсы |
| **Свой минимальный WebSocket-клиент** | Подключение к Tosu не зависит от undici; одинаковое поведение при отказах; проверено под Wine |
| **Inno Setup** | Стандартный установщик Windows без прав администратора; собирается в GitHub Actions |

Зависимости времени выполнения: только `rosu-pp-js`. Для сборки: `esbuild`, `postject`.

## Схема

```
osu! ──память──▶ tosu ──WebSocket v2──▶ TosuClient ─▶ TosuTracker ─┬─▶ attempts
                                                                   └─▶ ScoreService ─▶ scores (dedup)
osu.ppy.sh ◀──OAuth/REST── OsuApi ─▶ ProfileService ─▶ profile_snapshots, top_plays, scores
Songs/*.osu ─▶ SongsIndexer (osuParser + rosu-pp) ─▶ beatmaps + beatmaps_fts
                         PpService (rosu-pp, OsuFileSource: Songs → кэш → osu.ppy.sh)
                         FarmService (анализ профиля → прогноз → прирост → Farm Score)
HTTP API (/api/*) + SSE (/api/events) ─▶ браузер (web/)
```

## Модули (`src/`)

- `main.js` — запуск, один экземпляр, порт, открытие браузера, корректная остановка.
- `app.js` — сборка сервисов и все маршруты API (используется и тестами).
- `db/` — подключение, миграции (`PRAGMA user_version`), бэкапы `VACUUM INTO`.
- `integrations/tosu.js`, `wsClient.js` — соединение с Tosu и переподключение (1→5 с).
- `integrations/tosuTracker.js` — конечный автомат по кадрам Tosu: попытки и результаты.
- `integrations/osuApi.js` — osu! API v2, токены, лимит ~60 запросов/мин.
- `integrations/osuDetect.js` — поиск osu!stable и папки Songs (учитывает `BeatmapDirectory`).
- `songs/` — парсер .osu и инкрементальный индексатор.
- `scores/scoreService.js` — нормализация Tosu/API, дедупликация, слияние источников.
- `profile/` — снимки профиля, топ, lifetime pp, математика весов.
- `explorer/search.js` — FTS5 + фильтры в стиле osu! с эффективными параметрами модов.
- `pp/` — моды, обёртка rosu-pp, источник .osu, калькулятор с достоверностью.
- `farm/farm.js` — анализ профиля и рекомендации.

## Ключевые решения по данным

**Дедупликация.** `dedup_key = sha1(карта(md5) | режим | счёт | комбо | 300 | 100 | 50 | miss | моды)`.
Моды нормализуются (CL отбрасывается, NC = DT). Ник и дата в ключ не входят: ник может
смениться, а Tosu и API отдают дату с разной точностью. Дополнительно уникален
`api_score_id`. При совпадении записи сливаются: источники объединяются, официальные pp
из API заменяют оценку.

**Свои результаты.** Tosu-результат сохраняется, только если имя игрока совпадает с
ником профиля (или, если ник неизвестен, экран результатов открылся сразу после игры).
Повторы чужих игр и просмотр таблиц лидеров не попадают в базу.

**Lifetime pp.** Только по разнице общего pp аккаунта между снимками профиля (рост и
падение отдельно). Новые scores между синхронизациями дают оценку через пересчёт
взвешенного топа, никогда не простым сложением pp.

**Попытки.** Вход в состояние `play` начинает попытку; выход на `resultScreen` — пасс;
иначе — фейл (флаг `failed`) или выход. Скачок времени назад внутри `play` — рестарт.
Повтор чужой игры не считается попыткой.

## Тесты

`npm test` — 32 теста:
- `unit.test.js` — моды, парсер, математика pp и lifetime, поиск, rosu-pp, модель Farm;
- `data.test.js` — трекер Tosu, дедупликация Tosu↔API, индексатор, поиск, WebSocket-клиент;
- `app.test.js` — приложение целиком через HTTP: эмулированный osu! API, настоящий
  WebSocket-сервер вместо Tosu, разрыв связи, офлайн, перезапуск с сохранением данных.

`scripts/smoke-test.mjs` — проверка собранного exe как чёрного ящика (запускается в CI на Windows).
`scripts/fake-tosu.mjs` — эмулятор Tosu для ручной проверки без игры.
